# Building the models

ONNX model weights for super-resolution upscaling and frame interpolation, converted from
upstream PyTorch checkpoints for use with [StreamDock](https://streamdock.net).

Covers eight model families:

- **Real-ESRGAN** (`esrgan/`) -- super-resolution upscaling, general-purpose and anime
- **BSRGAN** (`bsrgan/`) -- super-resolution upscaling, blind degradation
- **Real-CUGAN** (`cugan/`) -- super-resolution upscaling, anime/general no-denoise
- **HAT** (`hat/`) -- super-resolution upscaling, transformer-based, high quality
- **SwinIR** (`swinir/`) -- super-resolution upscaling, Swin Transformer
- **Waifu2x** (`waifu2x/`) -- super-resolution upscaling, anime/illustration
- **RIFE 4.18** (`rife/`) -- frame interpolation for true N-times temporal upscaling
- **Face models** (`facedetect/`, `facerestore/`) -- YuNet face detection; GFPGANv1.4 and CodeFormer face restoration

All models are generated by the export scripts in this directory, which download the
original checkpoints from upstream GitHub releases and convert them to ONNX with
DirectML-compatible dynamic-batch support.

The upstream model weights and architectures remain the intellectual property of their
original authors. See [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) for full license
and attribution details.

### Upscaling ONNX conversion details (ESRGAN / BSRGAN / CUGAN / SwinIR / Waifu2x)

- **Opset**: 17
- **Input shape**: `[N, 3, 128, 128]` (N = batch size, dynamic) -- except HAT which uses `[N, 3, 64, 64]`
- **Output shape**: `[N, 3, tile*scale, tile*scale]`
- **Tile size**: 128x128 px for ESRGAN / BSRGAN / CUGAN / SwinIR / Waifu2x; 64x64 px for HAT (window_size=16 constraint)
- **Batch axis**: Dynamic (`N` symbolic dimension)
- **DirectML compatibility**: `Resize` nodes that use static size tensors are rewritten to
  use relative scales so DirectML recomputes correct buffer sizes at runtime regardless of N.

## RIFE 4.18 Frame Interpolation Models

RIFE (Real-Time Intermediate Flow Estimation) is used to generate intermediate frames,
matching a stream's frame rate to the display refresh rate (e.g. a 30 fps stream on a
120 Hz monitor -> 4x multiplier, 3 interpolated frames per source pair).

### Why rife4.18 instead of rife47/48/49?

Pre-built ONNX files exist for rife47/48/49 (yuvraj108c/rife-onnx), but those models
produce only t=0.5 (fixed midpoint) and are hard-capped at 2x interpolation. rife4.18
ships a `timestep` tensor input that accepts any value in (0, 1), enabling true N-times
interpolation for any display/source rate combination. HolyWu/vs-rife only distributes
rife4.18 as a PyTorch `.pkl` -- no pre-built ONNX exists publicly -- so the conversion
must be done locally using `export_rife_onnx.py`.

### RIFE model files

One ONNX per resolution tier. Each file covers all stream resolutions up to its padded
dimensions. Padded dimensions are multiples of 32 as required by the RIFE architecture.

| File | Padded resolution | Covers streams up to |
|------|:----------------:|---------------------|
| `rife/rife4.18_864x480.onnx` | 864x480 | 480p landscape |
| `rife/rife4.18_1280x736.onnx` | 1280x736 | 720p landscape |
| `rife/rife4.18_1920x1088.onnx` | 1920x1088 | 1080p landscape |
| `rife/rife4.18_2560x1440.onnx` | 2560x1440 | 1440p landscape |
| `rife/rife4.18_3840x2176.onnx` | 3840x2176 | 4K landscape |
| `rife/rife4.18_480x864.onnx` | 480x864 | 480p portrait |
| `rife/rife4.18_736x1280.onnx` | 736x1280 | 720p portrait |
| `rife/rife4.18_1088x1920.onnx` | 1088x1920 | 1080p portrait |
| `rife/rife4.18_1440x2560.onnx` | 1440x2560 | 1440p portrait |
| `rife/rife4.18_2176x3840.onnx` | 2176x3840 | 4K portrait |

`rife47.onnx` is a fixed-midpoint fallback used when no rife4.18 tier matches the stream
resolution.

### Runtime auto-selection

`RifeVideoStream.ResolveModelPath()` selects the correct tier automatically at stream
start based on the stream's width x height. It picks the smallest tier whose padded
dimensions fit the stream. No configuration is required. The model path property
(`ModelPath`) accepts a manual override if needed.

## Obtaining the models

### Via the build scripts (recommended)

Models are no longer bundled in the CI release zip. End users download them on first
launch via the in-app Model Manager, which reads URLs from `src/Configuration/Models/model-bundle.json`.

To build and publish a new set of models to the package registry (e.g. after an upstream
weight update), run:

```powershell
# Build all ONNX files and upload to the package registry
src\Scripts\build_and_upload_models.ps1 -Token <personal-access-token>

# Build locally without uploading
src\Scripts\build_and_upload_models.ps1 -LocalOnly
```

This script creates a Python venv, runs all export scripts, and uploads the results to
the GitLab package registry under `streamdock-models/<version>/`. It also patches
`src/Configuration/Models/model-bundle.json` with the resulting URLs, SHA-256 hashes, and
sizes.

The rife4.18 tiers are published separately, because they live in their own package
versioned to the upstream RIFE release — otherwise every RIFE update would force a version
bump of all the other models:

```powershell
# Upload each rife4.18_*.onnx tier individually to rife-models/<rife version>/
src\Scripts\upload_rife_tiers.ps1 -Token <personal-access-token>
```

### Building individual models locally

The export scripts live in this directory alongside the model files. They are fully
self-contained: they download both the architecture source files and the `.pth` checkpoints
directly from the upstream GitHub repositories. Temporary files (downloaded weights, arch
source) are cleaned up automatically after export; pass `--keep-tmp` to retain them.

### Real-ESRGAN models (x4plus, x2plus, animevideov3)

```
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install onnx onnxsim numpy onnxruntime

python export_esrgan_onnx.py [--out esrgan] [--models all|x2plus|x4plus|animevideov3] [--no-simplify]
```

`patch_esrgan_resize.py` is a standalone predecessor to `export_esrgan_onnx.py`. Its
dynamic-batch patching logic is fully integrated into `export_esrgan_onnx.py` and the file
is retained for reference only.

### BSRGAN models (bsrgan-x4, bsrgan-x2)

```
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install onnx onnxsim numpy onnxruntime

python export_bsrgan_onnx.py [--out bsrgan] [--models all|x4|x2] [--no-simplify]
```

Uses the same 128x128 tiled ONNX format and DirectML Resize patch as the ESRGAN export.
CPU-only PyTorch is sufficient.

and place them in `hat/_hat_export_tmp/`, then re-run (the script skips existing files).

`facedetect/face_detection_yunet_2023mar.onnx` is distributed pre-built from the

### Face restoration models (GFPGANv1.4, CodeFormer)

> **License note**: CodeFormer is released under the S-Lab License 1.0 which restricts
> use to non-commercial research purposes only. Do not include `CodeFormer.onnx` in
> commercial distributions without explicit permission from the authors.

```
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install onnx onnxsim numpy

python export_facerestore_onnx.py [--out facerestore] [--models all|gfpgan|codeformer] [--no-simplify]
```

Outputs fixed-shape `[1, 3, 512, 512]` models. No GPU needed.

> **Why `--no-simplify` / `dynamo=False`?** PyTorch 2.6+ defaults to the new dynamo
> exporter which splits weights into a separate `.onnx.data` file. `dynamo=False` (used
> internally by the script) keeps the legacy TorchScript path which embeds all weights
> inline, as expected by OnnxRuntime's single-file load.

Existing files are skipped, so the script is safe to re-run.
